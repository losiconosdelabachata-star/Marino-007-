# Deploying Marino 007

Moves the whole system off a local machine and onto Render: the dashboard,
the WhatsApp bridge, and the blog scheduler, all in one container.

---

## Why one container

The dashboard spawns the Python scripts directly and SQLite needs a single
writer on a single disk. Splitting these into separate Render services would
mean rewriting the control API as a job queue and migrating to Postgres — a
lot of machinery for a workload this size. One container, one disk.

**Vercel will not work.** The bridge is a long-lived socket, the schedulers
run continuously, and all three need a writable disk. Serverless has none of
those.

---

## Before you start

### 1. Rotate your keys

Do this first, not after. The Anthropic key, the Shopify API password, and
the Google OAuth client secret were all exposed in plaintext at various
points. You are about to type them into Render anyway — type the new ones.

- Anthropic → https://console.anthropic.com/settings/keys
- Shopify → admin → Apps → your custom app → rotate
- Google → Cloud Console → APIs & Services → Credentials

### 2. Mint Google refresh tokens

A server has no browser, so it can never complete Google's consent screen.
Run this once **locally**:

```bash
python get_refresh_token.py
```

It opens a browser twice, then prints the four values to paste into Render.
Keep the output — these are credentials.

### 3. Fix Google One billing

Google Photos currently returns 403 because of the failed payment. Deploying
does not change that. The blog engine will come up and sit idle until it is
resolved.

## Deploy

1. Push to GitHub (already done if you are reading this in the repo).

2. Render Dashboard → **New** → **Blueprint** → select
   `losiconosdelabachata-star/Marino-007-`.
   Render reads `render.yaml` and prompts for every secret.

3. Fill in the prompted values:

   | Variable | Where it comes from |
   |---|---|
   | `DASHBOARD_PASSWORD` | Pick one. This gates the whole dashboard. |
   | `ANTHROPIC_API_KEY` | console.anthropic.com |
   | `SHOPIFY_STORE` | `losiconosdelabachata.myshopify.com` |
   | `SHOPIFY_API_KEY` / `SHOPIFY_API_PASSWORD` | Shopify admin → Apps |
   | `PRINTIFY_SHOP_ID` / `PRINTIFY_API_KEY` | Printify (key still pending) |
   | `GOOGLE_OAUTH_CLIENT_ID` / `_SECRET` | from `get_refresh_token.py` |
   | `GOOGLE_PHOTOS_REFRESH_TOKEN` | from `get_refresh_token.py` |
   | `GOOGLE_DRIVE_REFRESH_TOKEN` | from `get_refresh_token.py` |
   | `EMAIL_SENDER` / `EMAIL_PASSWORD` | Gmail + an **app password** |
   | `MARINO_PHONE` | number that receives alerts |

   `SESSION_SECRET` is generated by Render — leave it alone.

4. Deploy. First build takes ~5–10 minutes (it compiles `better-sqlite3`).

5. Open `https://<your-service>.onrender.com` and log in.

6. **Re-link WhatsApp.** The session does not transfer from your laptop.
   Command tab → scan the QR with the dedicated phone. This is the one
   manual step after every fresh volume, but it survives redeploys because
   the session lives on the mounted disk.

## Plan and cost

`render.yaml` specifies **Starter**, not Free, deliberately. Free instances
sleep after 15 minutes of inactivity — that would drop the WhatsApp socket
and stop the schedulers, so orders would go unfulfilled and no blog would
publish. Roughly $7/month for the instance plus about $0.25/month for the
1 GB disk.

---

## What lives on the disk (`/data`)

| File | Why it must persist |
|---|---|
| `auth_info/` | WhatsApp session — losing it means re-scanning the QR |
| `affiliates.db` | Affiliates, messages, sales |
| `blog_tracker.json` | Which photos are already blogged (prevents duplicates) |
| `processed_orders.json` | Which orders are already fulfilled (prevents doubles) |
| `blogs/` | Generated posts |

Those last two matter more than they look: without them, a redeploy would
re-send orders to Printify and re-publish blogs that already went out.

## Operating it

**Logs** — Render dashboard → Logs. Every line is prefixed with which
process emitted it (`[whatsapp]`, `[dashboard]`, `[blog]`).

**Restarts** — the supervisor restarts a dead process with exponential
backoff. If a critical one crash-loops five times in a minute it exits, so
Render restarts the container and the failure is visible rather than silent.

**Running locally still works.** `DATA_DIR` defaults to the project folder,
so nothing about local development changed:

```bash
powershell -ExecutionPolicy Bypass -File start_command_center.ps1
```
